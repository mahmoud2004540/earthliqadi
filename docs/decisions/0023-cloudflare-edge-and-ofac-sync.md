# ADR-0023: Cloudflare edge location, sub-national restrictions, automatic OFAC screening

- Status: Accepted (owner request, 2026-11-06)
- Date: 2026-11-06
- Extends: ADR-0022
- Context: the owner wants the protection model of the reference
  non-custodial venue. Its published terms (last updated 2026-06-15) restrict
  persons in the United States and **Ontario, Canada**, persons in sanctioned
  territories, and **citizens** of sanctioned territories wherever they are.
  They forbid VPNs and proxies used to hide a location. Its interface refuses
  restricted locations. ADR-0022 had country-level checks only, and lists
  loaded by hand. This ADR closes those gaps. Counsel review is still
  required (product brief §8).

## Decision

### 1. Location from Cloudflare, trusted only from Cloudflare

Production runs behind Cloudflare. The edge proxy
(`infrastructure/docker/edge/nginx.conf`) handles location as follows.

**From a Cloudflare network:**

- It restores the client IP from `CF-Connecting-IP`.
- It forwards Cloudflare's location as `X-Edge-Country` (from `CF-IPCountry`)
  and `X-Edge-Region` (from `CF-Region-Code`).

**From any other network:**

- Both headers are sent **empty**.
- The client IP stays the TCP peer.

**Always:**

- Client-sent `X-Edge-*` values are overwritten.
- The `CF-*` headers are not forwarded to the API.

**How it was verified.** Against nginx 1.28:

- The real list is used and the client is not Cloudflare: no location is
  forwarded, and the IP is the peer.
- 127.0.0.1 is added to a test copy of the list: the location and the client
  IP are forwarded.
- A client sends `X-Edge-Country` itself: the value is dropped.

**Cloudflare networks.** The edge reads them from
`infrastructure/docker/edge/cloudflare/*.inc`. That file is generated by
`scripts/update-cloudflare-ips.sh` from Cloudflare's published ranges.

The API is configured with:

```
GEO_COUNTRY_HEADER=x-edge-country
GEO_REGION_HEADER=x-edge-region
```

The Cloudflare-side setup is described in `docs/operations/cloudflare-edge.md`.

### 2. Sub-national restrictions

`RESTRICTED_SUBDIVISIONS` takes ISO 3166-2 codes such as `CA-ON` for
Ontario.

**The region header.** Cloudflare sends the subdivision part ("ON"). A full
code ("CA-ON") is also accepted. A code naming another country is treated as
unknown.

**When a country has restricted subdivisions,** its requests need a known
subdivision. Without one, `GEO_UNKNOWN_COUNTRY` applies, and that is `deny`
in production.

**Config rules:** staging and production refuse to boot when subdivisions are
listed but no region header is configured.

**What a restricted subdivision blocks.** The same as a restricted country
(ADR-0022): no new accounts and no new risk. Sign-in, reduce-only orders,
cancels and withdrawals stay open.

**Published:** the list is published at `GET /v1/access`
(`restrictedSubdivisions`) and on `/terms`, with readable names.

**Suggested preset, for counsel to confirm.** It is not a code default:

```
RESTRICTED_COUNTRIES=US,CU,IR,KP
RESTRICTED_SUBDIVISIONS=CA-ON,UA-43,UA-40,UA-14,UA-09
```

- `US` and `CA-ON` mirror the reference venue's terms.
- The rest are territories under comprehensive OFAC sanctions:
  - Cuba, Iran, North Korea;
  - Crimea, Sevastopol;
  - Donetsk and Luhansk.
- Counsel must confirm the list against the sanctions programmes that apply
  to the operator (OFAC, EU, UK, UN …) and the operator's own jurisdiction.

### 3. Automatic OFAC SDN screening

OFAC publishes sanctioned wallet addresses inside SDN entries, as
"Digital Currency Address - TICKER address".

**What is screened.** `parseOfacSdnAddresses` extracts every `0x` address
with 40 hex digits, whatever the ticker (ETH, USDT, USDC, BNB, ETC …). Each of
these is an EVM account that could sign in here. Addresses on other chains
are skipped, because they cannot sign in.

**Automatic updates.** `SanctionsSyncService` downloads the official SDN
export every `SANCTIONS_SYNC_HOURS`:

- the source is `SANCTIONS_OFAC_URL`, https only;
- the first run is 10 s after boot;
- the download replaces the `ofac-sdn` source.

Production requires an interval between 1 and 24 hours.

**Fail-safe.** A failed download keeps the previous list, and so does one
that looks broken:

- no EVM addresses;
- fewer than half of the loaded addresses.

A failure is logged as `SANCTIONS_SYNC_FAILED`. Screening never silently
turns off.

**Manual run.** Operators run it with
`pnpm --filter @platform/api cli:sanctions sync-ofac [--file SDN.CSV] [--force]`.
`--force` accepts a genuine large removal. Every replacement is audited
(`access.sanctions.list_replaced`).

**Verified against the live list on 2026-11-06:** 94 EVM addresses were
loaded from the official export. The repository and the tests contain **no**
real list entries; the tests use synthetic rows.

### 4. Terms

The draft terms now define restricted persons the way the reference venue
does:

- residence, location or incorporation in a restricted jurisdiction;
- citizenship of a jurisdiction restricted for sanctions;
- acting for such a person;
- listing on a sanctions list.

A separate **no-circumvention** clause forbids:

- VPNs and proxies;
- false statements about residence or citizenship;
- using someone else's wallet.

The acceptance checkbox repeats these points. The text is our own wording and
remains a draft for counsel.

## What we deliberately do differently

The reference interface refuses restricted locations outright. Here, a
restricted location can still:

- sign in;
- reduce positions;
- cancel orders;
- withdraw.

This way funds are never trapped by geography or travel, which is stricter
for user safety, not looser for risk. Counsel may decide to tighten this.

## Limits

- **Location checks can be defeated** by VPNs and proxies. Cloudflare marks
  Tor as `T1`, which is treated as unknown and so denied in production. A
  commercial VPN cannot be detected by these headers. The terms forbid it.
- **Citizenship cannot be checked** without identity verification, and we do
  not do KYC (ADR-0013). That clause is enforced by the terms only.
- **OFAC only.** The EU, UK and UN lists rarely publish wallet addresses. A
  commercial screening provider (on-chain exposure, not just listed
  addresses) is a counsel and owner decision.
- **The escape hatch** of the vault contract cannot be blocked (ADR-0014).
